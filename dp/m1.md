# M1 — Pilot MVP 01 Engineering Execution Plan (macOS)

status: ready for assignment; implementation depends on the Phase 1 contract freeze

## Context

Pilot is a macOS-first desktop assistant that observes one user-selected window, follows the pointer, accepts push-to-talk spoken questions, and answers aloud, grounded in the screen. The repo currently contains four design docs (`docs/product-spec.md`, `docs/system-design.md`, `docs/mvp-01-point-ask-hear.md`, `docs/logic.md`) and no application code. This plan builds MVP 01 end-to-end to its **full definition of done** (docs/mvp-01 §19): packaged demo scenario, acceptance matrix A-01…A-15, three tested model profiles, ≥90% pointer grounding on a curated checklist, bounded/cleared frame memory.

Decisions fixed during the planning interview:

- **Target**: full MVP-01 DoD, not just a demo slice.
- **Form factor**: menu bar app + compact floating always-on-top panel (transcript, states, text input); menu bar owns observation status/pause.
- **Dev environment**: code lives in this repo; build/run/test iteration happens on an available Mac.
- **Agent layer**: Pi Agent Core + Pi provider package (`@earendil-works`, pinned exact versions), registry + docs available. A phase-1 spike validates the real API surface before anything depends on it.
- **Native layer**: a small Swift helper executable (SwiftPM) bundled in the app, spawned by the Electron main process, speaking a typed length-prefixed protocol over stdio. Owns ScreenCaptureKit, Accessibility, geometry, global PTT key events, Apple Speech STT, AVSpeechSynthesizer TTS, permission state.
- **STT**: Apple `SFSpeechRecognizer` via the helper. Pilot requests Speech Recognition permission separately from Microphone permission. It requires on-device recognition when supported; otherwise the UI discloses that recognition may use Apple's service and offers text input.
- **TTS**: `AVSpeechSynthesizer` via the helper.
- **Providers**: subscription = OpenAI Codex sign-in through Pi; API key = one vision-and-tools provider proven by the Phase 1 spike; local = one OpenAI-compatible endpoint with a capability-proven vision-and-tools model. Exact model IDs come from the pinned Pi catalog or a successful capability probe and are not hard-coded in this plan.
- **Signing**: development-signed builds only; Developer ID notarization deferred to a follow-up module and recorded as a known gap against the DoD word "signed".
- **Grounding test set**: manual checklist (~30 cases) over real apps (Finder, Safari, System Settings, TextEdit, …), documented in-repo and re-runnable by hand.

## Engineering ownership and effort

This plan assumes six engineers with exclusive primary folder ownership. Effort ranges are engineering days and include implementation, unit tests, and block-level documentation. They exclude review latency, provider outages, signing-account delays, and waiting for physical test hardware. Treat the ranges as planning estimates with roughly ±30% uncertainty, not delivery promises.

| Engineer | Workstream | Exclusive primary folders | Size | Estimated effort |
|----------|------------|---------------------------|------|------------------|
| E1 | Desktop Experience | `apps/desktop/` | M | 8–12 engineer-days |
| E2 | macOS Platform | `packages/platform-mac/` | XL | 15–22 engineer-days |
| E3 | Observation Engine | `packages/observation/` | L | 10–15 engineer-days |
| E4 | Agent Runtime | `packages/agent-runtime/` | L | 10–15 engineer-days |
| E5 | Voice & Interaction | `packages/interaction/` | L | 10–15 engineer-days |
| E6 | Contracts, Integration & Release | `packages/platform/`, `packages/shared/`, root config, `tests/` | L | 10–15 engineer-days |

Base effort is approximately **63–94 engineer-days**. Reserve 20% integration and platform-risk contingency, producing a planning range of approximately **76–113 engineer-days**. Six engineers do not reduce this to a simple one-sixth wall-clock schedule because the contract freeze, native spike, grounding integration, and packaged acceptance run are sequential gates.

### Ownership rules

- E6 owns cross-package contracts, root workspace configuration, integration tests, and release wiring.
- E1–E5 do not edit another workstream's primary folder. They request a contract change from E6.
- Each workstream exports one public facade and keeps implementation types private.
- Cross-block development uses fakes from `packages/shared` or a dedicated test-kit; engineers do not wait for another block's implementation when a contract and fake are available.
- The owner implements and tests a block; a different engineer reviews it.
- Platform-specific types may not leak into Observation, Interaction, Agent Runtime, or renderer APIs.

### Workstream deliverables

#### E1 — Desktop Experience

- Electron lifecycle, menu bar, floating panel, single-instance behavior, and validated renderer IPC client.
- Onboarding for Screen Recording, Accessibility, Microphone, and Speech Recognition permissions.
- Model settings, window picker, observation controls, transcript/response UI, status states, text fallback, and developer diagnostics view.
- Renderer tests and UI-level acceptance fixtures.
- Does not implement capture, speech, Pi, image processing, or credential storage.

#### E2 — macOS Platform

- Swift helper, explicit framed stdio protocol, helper supervision bridge, and permission/TCC reporting.
- ScreenCaptureKit window enumeration/capture, Accessibility hit testing, geometry primitives, CGEventTap global PTT, Apple STT/TTS, screen-lock/window-loss events, and fresh capture.
- Native unit tests where practical plus repeatable Mac smoke checks.
- Does not implement screen retention policy, agent prompts, or Electron UI.

#### E3 — Observation Engine

- Bounded ring buffer, pointer timeline, scene tracker, frame selection, screen policy, redaction, crop/annotation, and final image encoding.
- `ScreenContextService` implementation with cancellation, scene-lineage checks, rate limits, and deterministic clearing.
- Unit tests using synthetic frame and pointer fixtures.
- Does not call native APIs directly or depend on Pi types.

#### E4 — Agent Runtime

- Pinned Pi integration, model profiles, authentication facade, capability probing, session lifecycle, `observe_screen` tool, visual pruning, and compaction.
- Proves during Phase 1 that images can be excluded from durable session storage; uses an in-memory Pi session plus Pilot text persistence until that proof succeeds.
- Agent fakes and provider-independent tests.
- Does not access ScreenCaptureKit, AX, microphone, or renderer state.

#### E5 — Voice & Interaction

- Product state machine, push-to-talk orchestration, transcript lifecycle, `QuestionEnvelope`, interruption, stale-result rejection, response streaming, and TTS sentence buffering.
- Uses speech and agent facades; contains no Apple-framework or Pi-provider implementation.
- State-transition, segmentation, interruption, and envelope tests.

#### E6 — Contracts, Integration & Release

- Workspace scaffold, CI, lint/test/build commands, public interfaces, zod schemas, privacy-safe logging, errors, geometry contract, and fake adapters.
- Composition root connecting all real blocks, end-to-end scenarios, privacy tests, packaging, dev signing, acceptance records, and release documentation.
- Owns integration failures that span packages and assigns block-local defects back to their owner.

## Architecture

Monorepo (pnpm workspaces + TypeScript), matching docs/mvp-01 §16:

```text
apps/desktop/
  src/main/             Electron main: lifecycle, tray/panel, IPC validation, orchestration
  src/renderer/         React UI: onboarding, model settings, observation control, conversation panel
packages/shared/        types, zod-validated IPC contracts, privacy-safe logging, geometry
packages/platform/      PlatformAdapter interfaces (docs/system-design §5)
packages/platform-mac/  Swift helper (native/) + typed stdio bridge (src/adapter.ts)
packages/observation/   ring-buffer, scene-tracker, screen-policy, image-pipeline
packages/interaction/   controller (state machine), utterance envelope, tts-buffer
packages/agent-runtime/ Pi session lifecycle, model profiles, observe_screen tool
```

Runtime data flow (docs/system-design §3): helper streams JPEG frames (2–3 FPS, policy resolution) and 30 Hz pointer samples → observation engine keeps a 3 s in-memory ring + pointer timeline + scene revisions. PTT down/up (helper CGEventTap) drives the interaction state machine; STT transcript + `QuestionEnvelope` (text + scene/pointer metadata, **no image**) enters the Pi session. The model may call `observe_screen(view, moment)`; the screen-context service selects buffered/fresh frames, applies policy (redact → crop → annotate → resize → encode → context limits), and returns text metadata + image blocks. Streamed answer text is sentence-segmented into TTS; new PTT interrupts TTS ≤300 ms and aborts/steers the Pi run.

Key cross-cutting contracts (already specified in docs, reuse verbatim): `MVP_SCREEN_POLICY` (mvp-01 §10), `InteractionState` + transition table (§7), `GroundedPointer` (§8), `ObserveScreenInput/ScreenObservation` (system-design §9), `QuestionEnvelope` (§8), `ModelProfile` (§12).

Helper stdio protocol: 4-byte little-endian JSON-header length, followed by the JSON header, followed by exactly `payloadLength` binary bytes declared by that header. The header includes protocol version, message type, request/event ID, payload type, and payload length. Header and payload limits are enforced before allocation. Images travel as binary payload and are never logged. The helper is bundled in `Contents/Resources/` (or `Contents/MacOS/`), started/supervised by main, and restarted on crash with buffers cleared.

Persistence: preferences + model profiles (no plaintext secrets) as JSON in `app.getPath('userData')`; API keys via Electron `safeStorage` (Keychain-backed) unless the Pi spike shows Pi's own credential flow should own them; subscription tokens via Pi's flow; text-only session transcripts + summaries. Phase 1 must prove that raw image blocks cannot reach durable Pi storage. Until then, Pilot uses an in-memory Pi session and persists only sanitized text through its own adapter.

## Phase 1: Foundation & Pi spike

### Overview
Scaffold everything the vertical slice needs, and de-risk the two biggest unknowns (Pi API surface, helper TCC/permission attribution) before feature work.

### Work
- pnpm workspace, TypeScript project refs, Vitest, ESLint/Prettier; `electron-vite` for main/renderer bundling; `electron-builder` config (mac, dev signing) checked in early even though packaging lands in Phase 5.
- `packages/shared`: `src/ipc.ts` (zod schemas for every renderer↔main channel and every helper message), `src/logging.ts` (structured logger that hard-drops base64/audio/credential fields), `src/geometry.ts` (screen-points ↔ normalized-window ↔ captured-pixels; the only place conversions live), core types file mirroring the doc interfaces listed above.
- `packages/platform`: `src/types.ts` — `PlatformAdapter`, `ObservationAdapter`, `AccessibilityAdapter`, `SpeechInputAdapter`, `SpeechOutputAdapter`, `PermissionAdapter`, `WindowAdapter`, `CredentialAdapter` exactly as system-design §5.
- `apps/desktop`: Electron shell that boots, shows tray icon + placeholder panel window (frameless, always-on-top, hides rather than quits), validated IPC plumbing, single-instance lock.
- **Pi spike** (`packages/agent-runtime/spike/` + findings doc `docs/pi-notes.md`): install pinned `@earendil-works` packages; validate session creation, streaming events, tool registration/result-with-image-blocks, abort/steer, compaction primitives, OpenAI Codex subscription sign-in, one API-key vision provider, and one local OpenAI-compatible endpoint. Prove image pruning and sanitized persistence before using a durable Pi session. Output: pinned versions in root `package.json`, capability-proven provider profiles, and the thin wrapper API `agent-runtime` will expose.
- **Helper skeleton spike** (`packages/platform-mac/native/` SwiftPM exe + `src/adapter.ts` bridge): stdio protocol echo + `listWindows` + permission status; verify on the Mac that Screen Recording, Microphone, Speech Recognition, and Accessibility TCC prompts attribute to the parent app bundle when the helper is spawned as a child (top risk — if not, fall back to making the helper the bundle's main executable responsibility or an XPC-style embedded helper; record outcome in `docs/pi-notes.md`).

### Tests
- Geometry conversions across 1x/2x scales and negative-origin multi-display coordinates (unit).
- IPC schema round-trips + rejection of oversized/unknown messages (unit).
- Logger redaction: base64/credential-shaped fields never serialized (unit).

## Phase 2: Observe (Checkpoint A)

### Overview
Real selected-window observation: enumerate → select → capture → bounded local ring → pause/clear. Ends with the doc's Checkpoint A criteria.

### Work
- Helper (`native/`): window enumeration with stable IDs; ScreenCaptureKit stream for one window at `sampleFps: 3`, intermediate ring frames encoded once at high quality and ≤1440 px longest edge before crossing stdio; 30 Hz pointer sampling with coalescing; AX hit-testing (`elementAt`) returning role/label/value/bounds + `isSecure` flag; screen-lock and window-closed events; `captureFresh` command. Phase 2 measures small-text readability so the Phase 4 pipeline does not introduce unacceptable double-JPEG degradation.
- `packages/platform-mac/src/adapter.ts`: typed bridge implementing `ObservationAdapter`/`AccessibilityAdapter`/`WindowAdapter`/`PermissionAdapter`; helper process supervision (spawn, health, restart⇒buffers cleared).
- `packages/observation`: `ring-buffer.ts` (time+byte bounded: 3000 ms / 16 MiB, deterministic clear), `scene-tracker.ts` (sceneId/revision from window identity, geometry, AX root, frame fingerprint), `screen-policy.ts` (`MVP_SCREEN_POLICY` const + enforcement helpers).
- Renderer: onboarding surface (permission explain/status/retry/System Settings deep links for Screen Recording, Accessibility, Microphone, and Speech Recognition); window picker with app name/title preview; observation controls (start/pause/resume/change); persistent tray "Observing <App>" state; **diagnostics view** (dev-only) showing live ring stats, latest frame, pointer target — this is how Checkpoint A is demonstrated. Accessibility denial disables global PTT and semantic hit testing but preserves text input and visual pointer-coordinate fallback.
- Lifecycle enforcement: pause, window close, screen lock, permission revocation ⇒ stop capture + clear ring + clear pointer timeline (A-07, A-10 groundwork).

### Tests
- Ring eviction by time and byte ceiling; timestamp-nearest frame selection; clear-on-pause (unit).
- Scene revision changes on window switch/resize/content fingerprint change (unit).
- Manual on-Mac: only the selected window's content appears in ring; pause empties diagnostics instantly.

## Phase 3: Ask & Hear (Checkpoints B + D)

### Overview
Voice loop + agent loop with a **mock** `observe_screen`: PTT → STT → Pi session using the capability-proven Phase 1 profile → streamed answer → sentence-chunked TTS → interruption. Grounding images come in Phase 4.

### Work
- Helper: global PTT via CGEventTap (down **and** up events — Electron `globalShortcut` can't detect key-up; Accessibility permission is required for the global shortcut); default shortcut **hold Right Option (⌥)** — a single modifier CGEventTap can track via flags-changed without swallowing typed input — configurable in settings; `SFSpeechRecognizer` + `AVAudioEngine` streaming partial/final transcripts, separate Speech Recognition permission, on-device recognition required when available, audio buffers released on finalization/failure; `AVSpeechSynthesizer` speak/stop with utterance IDs (stop latency measured). When Accessibility is unavailable, an in-panel hold-to-talk control remains available.
- `packages/interaction`: `controller.ts` — the §7 state machine exactly (states, transition table, pause/error edges), stale-result rejection by utteranceId; `utterance.ts` — builds `QuestionEnvelope` (transcript, sceneId/revision/lastObservedRevision, pointer at PTT-release in normalized window coords + AX summary; pointer-outside-window reported honestly per §8); `tts-buffer.ts` — sentence-boundary segmentation with timeout-based phrase fallback.
- `packages/agent-runtime`: `session.ts` (Pi session lifecycle, conversationId↔Pi-session mapping, one active run per conversation, abort/steer wiring), `model-profile.ts` (profile store + capability gating: visual mode blocked unless `supportsVision && supportsTools` from Pi metadata or a capability probe), `observe-screen.ts` registered with real schema but returning a typed mock/unavailable result this phase; system prompt per §9 incl. screen-text-is-untrusted and on-screen-text-cannot-override-policy instructions.
- Renderer panel: listening/transcribing/thinking/speaking/error states, live transcript + streamed response, text-input fallback, stop-speaking + clear-conversation actions; distinct mic-active indicator.
- Interruption path: new PTT-down ⇒ TTS stop (≤300 ms target, measured) + abort or steer active run; late STT results dropped by utteranceId (A-08 groundwork).

### Tests
- State machine transition table + illegal-transition and stale-utterance rejection (unit).
- Sentence segmentation incl. abbreviations, code spans, no-terminal-punctuation timeout flush (unit).
- Envelope building from recorded pointer timelines, incl. outside-window case (unit).
- Manual on-Mac: full voice round-trip with the verified API-key profile; interrupt mid-speech; text fallback with mic denied (A-03, A-08, part of matrix).

## Phase 4: Ground (Checkpoint C)

### Overview
Real `observe_screen` + the screen-context policy pipeline + visual context retention. After this phase the demo scenario works end-to-end.

### Work
- `packages/observation/src/image-pipeline.ts` (runs in main, `sharp`, never blocks renderer): redact AX-flagged secure-field rects → pointer crop 640 px bounded to frame → pointer marker annotation on all outgoing images → resize full frame ≤1440 px → JPEG q0.75 (PNG only when small-text legibility demands).
- Screen-context service (`packages/agent-runtime/src/observe-screen.ts` + `packages/observation`): execution order per system-design §10 — validate observation active + window/scene lineage (reject frames from a previous selection: A-13/§15 "Frame no longer matches"), select frame by `moment` (`question` = ring frame nearest utterance anchor; `current` = `captureFresh`; `before-and-after` = ≤2 frames around latest scene transition), resolve anchored pointer + AX target, pipeline, enforce active-context limits (1 full + 1 crop; 2 fulls only in comparison), return compact JSON text part + Pi image blocks; ≤2 observation calls/sec; abort-signal aware; typed user-explainable errors (paused, permission lost, protected content, window gone).
- Visual context pruner: before each provider request replace obsolete image blocks with `[Observation removed: scene N, revision M. <one-line summary>]`; trigger Pi compaction after 4 observations or when estimated context usage exceeds 60% (use Pi's token/usage metadata if the pinned release exposes it; otherwise a chars/4 heuristic over active messages + fixed per-image token costs); compaction prompt preserves goals/decisions/named UI elements/unresolved questions, never claims old screens are current; session-persistence adapter guarantees no image bytes reach disk (A-12, A-14).
- Renderer: "observing-screen" state surfaces during tool runs; "Look now" manual observation action (failure-table row for models that don't call the tool).

### Tests
- Policy enforcement: size caps, crop bounds at frame edges, marker placement across 1x/2x, redaction rects, active-context eviction order (unit, `sharp` against fixture PNGs).
- Frame selection per `moment` from synthetic rings; lineage rejection; rate limiting (unit).
- Pruner: image blocks replaced, summaries inserted, compaction trigger counting (unit).
- Manual on-Mac: A-02, A-04, A-05 (tooltip preserved via `question` moment), A-06 (≤2 comparison frames), Retina marker alignment (Checkpoint C).

## Phase 5: Stabilize, Providers & Ship (Checkpoint E)

### Overview
Failure handling, the full provider trio, packaging, and the complete acceptance pass — everything §19 requires.

### Work
- Model settings UI: provider/model/auth-mode/endpoint-locality display, remote-vs-local labeling, capability validation results, API-key entry (safeStorage), OpenAI Codex subscription sign-in through the pinned Pi flow, and a local OpenAI-compatible base-URL profile with endpoint status; secrets never enter renderer state or logs.
- Failure behaviors per mvp-01 §15 table: permission revocation mid-session, window closure, protected/blank capture, auth expiry (preserve transcript, reauth, retry with consent), model request failure retry, STT/TTS failure fallbacks, tool-called-while-paused typed result.
- Buffer-clearing sweep: pause/lock/logout/window-loss/shutdown paths all verified to clear frames + audio (A-07 revisited, DoD "demonstrably cleared").
- Packaging: `electron-builder` mac build, helper bundled + dev-signed with entitlements, packaged app passes A-15 (no terminal, no user-managed second process); repeatable `pnpm build && pnpm package` documented in root `README.md` with known-issues list (notarization gap recorded).
- `docs/grounding-checklist.md`: ~30 point-and-ask cases across Finder, Safari, System Settings, TextEdit, Activity Monitor, a web dashboard — each with target, question, pass criterion, and a result column; run on one standard-DPI and one Retina setup; DoD needs ≥90%.
- `docs/acceptance.md`: A-01…A-15 run log template; execute full matrix on packaged build with all three profiles exercised (subscription, API key, local).

### Tests
- Provider capability gating incl. non-vision model block before send (A-11) (unit).
- Auth-expiry recovery state flow (unit with mocked Pi errors).
- Manual on-Mac: full acceptance matrix + grounding checklist; metrics spot-check against §17 budgets (time-to-first-token, first-spoken-sentence, interrupt latency).

## Decisions Log

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Scope | Full MVP-01 DoD | Demo slice first | User wants the complete checkpointed build in one module |
| Form factor | Menu bar + floating panel | Standard window | Persistent indicator + low footprint per spec principles |
| Native embedding | Swift helper process over stdio | N-API addon | Crash isolation, plain SwiftPM builds, matches docs' "embedded helper"; ABI/codesign simpler |
| STT / TTS | Apple Speech / AVSpeechSynthesizer via helper | whisper.cpp / cloud | Zero extra runtime, on-device, fast interrupt; adapters keep swap path open |
| PTT capture | CGEventTap in helper | Electron globalShortcut | globalShortcut has no key-up event; hold-to-talk needs down+up |
| Image ops | `sharp` in Electron main | CoreGraphics in helper | Keeps policy+pixels in portable TS (Windows boundary); async libvips avoids blocking |
| Providers | OpenAI Codex subscription + proven API-key profile + proven local compatible profile | Anthropic-centric trio | Uses the known subscription path while keeping exact model IDs capability-driven |
| Secrets | Electron safeStorage (Keychain-backed) / Pi's own flow for subscription | keytar, raw Keychain via helper | keytar unmaintained; safeStorage is maintained and Keychain-backed; spike may hand ownership to Pi |
| Signing | Dev-signed only | Developer ID + notarization | No Developer ID account yet; recorded as known gap |
| Grounding set | Manual checklist over real apps | Purpose-built test app | User preference; realism over determinism |
| Sessions | Text-only persistence via adapter | Pi default serialization | Guarantees no raw frames on disk regardless of Pi internals |

## Risks

1. **Pi API mismatch with docs' assumptions** — mitigated by Phase-1 spike before anything depends on it; agent-runtime wraps Pi behind a thin internal interface.
2. **TCC permission attribution for the spawned helper** — spiked in Phase 1 with named fallbacks.
3. **Subscription or model capabilities may differ in the pinned Pi release** — the spike validates Codex sign-in and resolves all exact model IDs before profiles are exposed.
4. **SFSpeechRecognizer availability, privacy, quality, or latency** — request Speech Recognition permission separately, prefer required on-device recognition, disclose remote fallback, and keep adapters compatible with a future whisper.cpp implementation.
5. **Double JPEG encoding may damage small text** — use a high-quality intermediate frame, measure legibility in Phase 2, and permit PNG for text-heavy observations.
6. **`sharp` prebuilds inside packaged Electron (arm64)** — validated during Phase 4 on the Mac, not at packaging time.
